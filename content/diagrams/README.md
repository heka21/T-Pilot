# Diagrams and widgets: the style guide

Every visual in the notes is either a **diagram** (`content/diagrams/<slug>.svg`, static SVG, may animate with
CSS) or a **widget** (`content/widgets/<slug>.html`, an Alpine.js component, optionally a Three.js explorer).
Notes reference them with image syntax; the caption is the question the visual answers and the optional
title is the one-line "What to notice":

```markdown
![Why does stall speed rise in a turn?](diagram:stall-speed-vs-bank "Beyond 45° the curve steepens fast: 60° costs 41%, 75° costs 97%.")
![Explore bank angle, load factor and stall speed](widget:bank-angle)
```

`python -m app.seed.check_content` enforces the rules marked **lint**. `python -m tools.diagrams.render` writes
light and dark PNG renders to the scratchpad for review (ImageMagick).

## Canvas and structure (lint)

- `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 640 360" role="img" data-prefix="xx">` with a
  `<title>` as the first child and a `<desc>` as the second. Width is always 640; use a taller viewBox
  (`0 0 640 420`, `0 0 640 480`) when the content needs it, never wider. Do not set `width`/`height`.
- No `<image>`, `<script>` or `<foreignObject>`. Under 40 KB. File name is a lowercase slug.
- `<style>` is allowed for animation only. Every class and `@keyframes` name inside it starts with the
  `data-prefix` (e.g. `.fsc-piston`, `@keyframes fsc-spin`) and no `#id` selectors (ids are rewritten when
  the SVG is inlined so `url(#arrow)` and `href="#x"` keep working, selectors would not).
- Generated files start with `<!-- generated by tools/diagrams; do not edit -->`.

## Colour (lint)

Only CSS tokens, so diagrams follow light and dark mode: `fill="var(--color-brand)"`. Never hex, rgb or
named colours. Never pure white or black: use `var(--color-surface)` and `var(--color-fg)`.

| Token | Use |
|---|---|
| `--color-fg` | outlines, primary text, the aeroplane silhouette |
| `--color-fg-muted` | secondary labels, axis titles |
| `--color-fg-faint` | tick labels, construction notes |
| `--color-line`, `--color-line-strong` | grids, construction lines, axes |
| `--color-surface`, `--color-surface-2` | panel backgrounds, the sky, instrument faces |
| `--color-brand` / `--color-brand-soft` | **the one thing the diagram explains** (lift vector, the curve, the active component) |
| `--color-ok` / `--color-ok-soft` | normal, safe, correct, green arc |
| `--color-warn` / `--color-warn-soft` | caution, limit approaching, amber |
| `--color-bad` / `--color-bad-soft` | danger, exceeded, stalled, red |
| `--color-info` / `--color-info-soft` | a second quantity contrasted with the brand one (drag vs lift, weight vs lift) |
| `--color-sky-soft` / `--color-sky-fg` | air, sky, water |
| `--color-tarmac` / `--color-paint` | runway and taxiway surfaces and their painted markings (dark surface, light paint in both themes) |

One focal element in brand colour; everything else quieter. Soft fills at full opacity, or main colours
with `fill-opacity="0.15"` for areas.

## Lines, text and arrows

- Stroke widths at 640 wide: 2 main, 1.25 secondary, 1 construction (dashed `4 3`). `stroke-linecap="round"
  stroke-linejoin="round"` on everything that is not an axis.
- Text: `font-size` 13 to 15 for labels, 16 to 18 for a panel heading, **never below 11 (lint)**. Do not set
  `font-family` (inherited from the page: Inter). Numbers and units: `class="num"` (JetBrains Mono).
  Keep 8 px clear between text and any stroke; never put text across a line.
- Arrowheads: one local marker, `<marker id="arrow" viewBox="0 0 8 8" refX="7" refY="4" markerWidth="6"
  markerHeight="6" orient="auto-start-reverse"><path d="M0 0 L8 4 L0 8 z" fill="context-stroke"/></marker>`.
  Force vectors are arrows with 2 px stroke, from the point of application, length proportional to size when
  sizes are compared.

## Conventions the exam uses

- The aeroplane flies **left to right**. Side views show the left side; the pilot's left is the reader's left
  in rear views, and is labelled when the view is from the front.
- Lift perpendicular to the relative airflow, weight vertical from the CG, thrust along the longitudinal
  axis, drag parallel to and opposite the relative airflow.
- Southern Hemisphere: anticlockwise around a high, clockwise around a low. Wind arrows point where the
  wind blows **to**; a wind sock or feather is the only exception.
- Units: knots and feet, except runway lengths and visibility in metres and kilometres. Australian airspace
  classes and chart colours. Numbers quoted on a diagram must match the note it sits in.

## Recurring characters

Reuse the shared silhouettes in `tools/diagrams/svg.py` (`plane_side`, `plane_top`, `plane_rear`, `runway`)
so the same aeroplane and runway appear everywhere. The aeroplane is the **Cessna 152** the student flies: a high
strut-braced wing on the cabin roof, tricycle gear with the main wheels just behind the CG, a swept fin with a
dorsal fillet and a low tailplane. All three views put the CG at (x, y), about 100 units long or across at scale 1,
nose to the right. Side view: spinner at x 55, rudder at x −50, wing on the roof at y −19 to −24 (leading edge
x 8, trailing edge x −14), belly y 7.5, wheels touch y 19.5 (nose wheel x 30, mains x −8). Plan view: wing x −5 to
11, tapering beyond |y| 28 to tips at |y| 50, ailerons from |y| 28 to 46. Rear view: wing y −21.5 to −16.5 across
±50, fin top y −34, wheels touch y 17 (mains at x ±9). So a lift arrow starts at the wing (about 21 units above the
CG), a chord line runs along y ≈ −21.5, and an aeroplane on the ground sits with its CG 19.5 × scale (side) or
17 × scale (rear) above the ground line. `airliner_rear` is the twin-jet "heavy" seen from behind (gear up, tips
at x ±50) for wake-turbulence pictures; a scaled-up Cessna does not read as a heavy. Widgets paste the same
markup, printed by `python -m tools.diagrams.plane` (see `tools/diagrams/README.md`). The sketch register (Rough.js, built by
`npm run sketch` from `tools/diagrams/schematics/`) is for concepts and systems; charts and anything with real
numbers stay crisp (generated by `tools/diagrams/charts.py`).

## Animation

CSS `@keyframes` in a `<style>` block, 2 to 8 s loops, `ease-in-out` unless it is rotation. Only one thing
moves per diagram. `transform-box: fill-box; transform-origin: center` for rotating parts. The app
stylesheet stops all `.visual` animation under `prefers-reduced-motion`, so diagrams need no media query.

## Widgets

A widget file is one root element: `<div class="widget" x-data="{ ... }">` containing, in order, the picture
(`<svg>` with Alpine bindings, or `<div class="widget-canvas" data-widget="explorer-name" ...>` for Three.js),
`.widget-controls` (a `.widget-control` per slider with `<label>` + `<output>`), `.widget-readouts`
(`.widget-readout` with `.widget-label` and `.widget-value`; add class `bad`/`warn`/`ok` and a
`.widget-flag` when a threshold is crossed), `.widget-actions` (presets in `.widget-presets`, a Reset button),
`.widget-notice` (**required, lint**: one line starting `<strong>What to notice.</strong>`) and optional
`.widget-try` `<details>` prompts that double as exam practice. Defaults are a realistic case (52 kt stall,
30° bank). Numbers are shown with their units. No network access (lint), no hex colours outside `<script>`
(lint). Maths in notes and widgets is KaTeX: `$...$` inline, `$$...$$` display.
